The canonical endpoint is `/mcp`. Discovery, tool and resource lists use the same
server registry. The supported protocol versions are `2026-07-28` and
`2025-11-25`; `/agents` is the native person's policy, activity and approval door.

Business access tokens require signed installation trust, a durable Business
person ID supplied by signed Business settings, an active native operator and
current Uptime role/service/team permission. An email match grants no authority.
A live native `monitoring:read` credential can use the read tools through MCP;
it retains its selection, creating operator and read-only ceiling. Runner,
heartbeat and metrics credentials retain their separate native protocols.

The current registry supports scoped monitor summaries, immutable history,
reports, separately granted failure evidence, monitor creation and ordinary
public definition updates/pause/resume, incident assignment/acknowledgment/notes,
maintenance and exact-preview route changes, native definition-file inspection,
evidence grants and a read-only native witness. Resources expose these records
without request or destination secrets. Target and imported text is untrusted.

Start a monitoring shift by reading the monitor and scheduled evidence. Retain
competing target, network and check hypotheses. Coordinate the incident, then
propose the smallest native monitor or routing change. Inspect independently
observed scheduled evidence afterwards. Acknowledgment and a manual check do not
prove recovery. No remediation, successful payment, refund, paging provider or
human receipt is implied.

Company policy chooses autonomous, review, approval or blocked dispositions;
there is no product approval preset. Unset, expired, unanswered and paused policy
refuse calls. Held mutations retain a server summary and its hash; the actual
named person decides the exact revision. Native role, consent, revision and
credential restrictions remain separate. Secret entry and native fresh-factor
requirements, monitor-kind changes and assertion-semantic edits remain in their native person doors. Protected monitor changes
currently return `native_proof_required`; no credential or private-network
fallback is supplied.

MCP does not yet expose manual checks, discovery starts, destination changes or
sends, definition-file apply, operator-access changes or privacy erasure. Use
those existing native person and installation doors with their original
permissions. The current definition-file tool inspects a file; it does not apply
or activate its contents.

Spend caps are not enforced. Native quotas, explicit effect grants and uncertain
provider outcomes remain binding. The monitoring door does not provide a
remediation executor or a general payment product.
