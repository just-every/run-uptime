# Saved Pingdom check details

Choose saved HTTP check-detail responses or TMS detail responses in Settings › Backup and files.
The [published API 3.1 schema](https://docs.pingdom.com/API_3.1.yaml), read
23 October 2026, defines HTTP details inside `check` and direct TMS detail objects
whose type is `script` or `recording`. Summary check lists do not supply complete
HTTP settings and are not treated as details.

HTTP conversion retains the existing cadence, literal inclusion/exclusion criteria,
credential references and certificate policy. Tag names now become monitor labels;
source tag type and usage count confer no routing authority. Every requested probe
filter is named and refused because this installation has no equivalent geographic
location choice. Review placement under PROBE-001 before converting those checks.

Transactions remain unsupported and name FLOW-001/FLOW-002. Their script steps are
withheld before upload because arbitrary form values can contain credentials. Other
unsupported types name their owning monitoring clause. Preview reconciles each
record; reviewed apply creates paused definitions, re-import is unchanged, and undo
retains created monitors paused with their history.

A page-speed saved-export shape was not established in the published schema, so
none is guessed. Live extraction, transaction/page-speed conversion, teams, contacts,
schedules, history, Lamp handoff and account cutover remain separate work. ROUTING-002's
existing saved contact delay/repeat/recovery preview is unchanged.
