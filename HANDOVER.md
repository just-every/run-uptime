# Uptime maintenance handover

## Commands and runtime

Use the **Run it locally** section in [AGENTS.md](AGENTS.md): `rer install`, `setup --owner-email EMAIL`, `dev`, and dev’s browser sign-in handoff after the printed `RER_READY` address is ready. Keep access credentials private; no captured-mail page is exposed. The signed-in first-run page is `/setup`; completion is installation-local D1 state. `/claim` hosts the one-use token form for an unclaimed hosted installation. Setup stops its temporary runtime; dev starts Vite assets/HMR, the synthetic target and signed private runner, staying in the foreground in a terminal or returning once ready in a non-interactive shell (`--detach` requests a background run); `rer dev --stop` stops them. `verify` runs the complete product and browser checks. `describe --json` and `check --profile first-party` are read-only. [OPERATIONS.md](OPERATIONS.md) covers reset, data movement, deployment and recovery.

The app origin serves the Lobby at `/`, setup at `/setup` and public documentation at `/docs`; `/app` is the private operator console. Package mode uses the published `@runeditrun/rer` 0.2.22 package for the CLI and deploy-kit integration; do not vendor those Base components. Keep Uptime's seed adapter explicit and preserve its target validation and authorization guards. Package-mode runtime acceptance is an external exact-candidate result. Release-pack verification uses the official current Base CLI producer independently of the product package. `scripts/installer/local.mjs` declares the shared lifecycle hooks and product targets. `rer-setup.json` is the sole setup manifest. `scripts/local` supplies the real runtime, migrations and complete product transfer. Settings remain in `data/local-secrets.json`; state is `.wrangler/state`. Existing owners, data and exact private settings survive setup. Reset is confirmed and contained. No automatic credential rotation is supported.

## Durable requirements

Preserve immutable definitions and attempts, fixed selected-probe coverage, scheduled-only confirmation/recovery and atomic evidence/state/outbox/job writes. Missing or stale evidence stays Unknown. Contact freshness proves authenticated receipt time, not process liveness or target health. Each independently keyed runner retains its installation-local identity across restarts. Every signed attempt must satisfy its immutable revision assignment, acceptance window, probe, clocks, transport and assertion bundle.

Public HTTP targets validate every DNS answer and redirect hop. Private runners pin sockets and retain TLS identity; hosted checks use Cloudflare’s public Internet transport. Runner-local credentials bind one monitor ID from the authenticated task and an exact origin; legacy files with exactly one existing referencing monitor (including paused monitors) bind during setup; shared or unused files need explicit owner binding via numbered migration 0001 documented in docs/runner.md. Discovery and browser-flow requests, including public subresources and WebSockets, use the runner's filtering and bounded-read paths. Independent egress isolation remains an operating requirement. Synthetic fixtures require exact process/path/port grants.

Archives carry product definitions, immutable evidence, destination definitions and the notification history that remains in the source. Receiving definitions remain paused, destinations disabled, leases interrupted and alerts quarantined. Restore transformations retain original records in archive history. Sessions, runner/heartbeat authority, grants, request credentials, webhook/Slack URLs and signing keys stay installation-local. The owner accepted this archive policy on 2026-10-13; available email addresses remain portable destination definitions. Local CLI restore requires the receiving checkout's `rer setup --owner-email EMAIL --non-interactive` before import into empty product data. If canonical local D1 already has active owners, setup requires its configured owner email to match one; with multiple active owners, configure one explicitly. Historical latency compatibility applies only to inactive restore; live results use conservative completion validation. Imported alerts never replay.

An owner can erase a monitor, destination or operator and its dependent records. Erasure leaves a per-table receipt and opaque audit entry; erasing an operator anonymizes that operator's earlier audit actor references. Destination erasure also removes dependent notification jobs, delivery attempts and outcomes, replay entries, and matching archive-history copies. Later exports carry the source erasure journal, which fences restored source records and erased-operator actor references. An older offline archive cannot show later erasures without the separately exported later journal. The last active owner cannot be erased; local reset or hosted replacement establishes a new owner.

Notifications cover installation-wide email, signed JSON and Slack. The hosted Worker sends email through the selected Base mail adapter and sends webhooks and Slack without a private runner. Owner-console requests prompt due checks and sends while it is open; the one-minute Cron trigger continues background work, with initial Cloudflare activation taking up to about two hours. Private runners remain required for heartbeats, discovery and private targets and can also claim notification work. Preserve the session secret while D1 contains encrypted credentials. Each event/destination has one automatic attempt; uncertain outcomes never retry automatically. Receiver acknowledgement does not prove human receipt.
