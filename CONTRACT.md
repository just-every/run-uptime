# Product contract

## Published clauses

The clauses below are stable public requirements. The linked sections give their complete interpretation and limits.

- **HTTP-001 — Signed HTTP monitoring.** HTTP(S) and keyword checks run through the separately scoped Node runner, retain the exact immutable assertion bundle and bounded transport evidence, and require authenticated claims and signed results; the control plane must reject contradictory completion. See [Integrity and authority](#integrity-and-authority) and [Network and credentials](#network-and-credentials).
- **EVIDENCE-001 — Immutable scheduled evidence.** Definitions, scheduled slots and every retry attempt retain revision, policy, fixed selected probes, runner identity, timings, status, assertions and error category; retries never erase failures, and observation/state/outbox commit atomically. See [Evidence and state](#evidence-and-state) and [Integrity and authority](#integrity-and-authority).
- **STATE-001 — Fixed coverage and incident hysteresis.** Missing or expired passing coverage is Unknown, partial failure stays visible, fixed quorum and scheduled confirmation determine Failing, and complete fresh scheduled passing evidence plus recovery threshold is required for recovery; manual checks and maintenance never rewrite observations or scheduled policy. See [Evidence and state](#evidence-and-state).
- **AUTHORITY-001 — Server-side scoped authority.** Every private document, read, mutation and export requires server-side operator or scoped runner authority, missing configuration fails closed, browser mutations enforce configured origin, and expired/foreign/duplicate leases cannot alter current evidence; a signature identifies a key holder rather than proving truthful observation. See [Integrity and authority](#integrity-and-authority).
- **NETWORK-001 — Pinned bounded destination execution.** Every public DNS answer and redirect hop is validated fail closed, numeric sockets preserve Host and TLS identity, unsafe/mixed addresses and HTTPS downgrade are rejected, cross-origin redirects strip request authority, and synthetic grants and protected origin-bound local credential files retain their separate custody limits. See [Network and credentials](#network-and-credentials).
- **HEARTBEAT-001 — Revision-scoped receipt evaluation.** Hashed owner-issued tokens and increasing sequences protect server-time receipts, ingress cannot advance health, and scheduled signed completion must match its exact installation-local claim snapshot; stale, future, paused, foreign-revision or imported receipts cannot establish Healthy. See [Network and credentials](#network-and-credentials).
- **ARCHIVE-001 — Inactive validated restore.** Bounded versioned archives require integrity and semantic validation before transactional restore into an empty installation, preserve historical evidence, create paused current revisions, interrupt leases and quarantine alerts; installation-local sessions, keys, grants, request execution, heartbeat authority, contact and delivery credentials are excluded; destination definitions and notification histories are portable, and imported evidence cannot establish current health or replay events. See [Portability and retention](#portability-and-retention) and [Integrity and authority](#integrity-and-authority).
- **RETENTION-001 — Explicit storage custody.** Metadata has no automatic deletion, raw target response bodies and probe-request secrets are not retained in observations, notification credentials remain installation-local, view/archive bounds are not deletion or capacity claims, and retention changes must never silently improve the fixed denominator or historical health. See [Portability and retention](#portability-and-retention).
- **PRESENCE-001 — Contact separate from health.** Only accepted scoped claims and signed results refresh server-time contact, the 120-second freshness threshold never proves process liveness or target health, and restart, unavailable reads and archive omission preserve that distinction. See [Contact, interface and delivery](#contact-interface-and-delivery).
- **INTERFACE-001 — Honest durable operator feedback.** Textual state/freshness/reasons, immutable history, labels, keyboard controls and responsive layout expose persisted evidence; failed reads show Unknown, action errors survive polling, busy reconciliation excludes controls and editing rejects assertion overrides. See [Contact, interface and delivery](#contact-interface-and-delivery).
- **NOTIFY-001 — Authorized installation-wide destinations.** An owner may configure email, signed JSON webhook, or Slack incoming webhook destinations for all monitors in one installation; only scheduled incident transitions generate automatic notifications, and a test send cannot change monitor evidence or incident state. Email uses the configured SendGrid sender and is submitted when the private runner polls; the runner sends webhook and Slack requests. Destination credentials are installation-local and are not restored from archives. See [Contact, interface and delivery](#contact-interface-and-delivery) and [Network and credentials](#network-and-credentials).
- **DELIVERY-001 — Bounded notification acknowledgement.** Each event and destination gets one automatic send attempt. HTTP 500, connection loss, timeout, and unknown outcomes remain uncertain and are not automatically sent again. Accepted means the configured provider or endpoint acknowledged the request; it does not mean a person received, read, or acted on it. See [Contact, interface and delivery](#contact-interface-and-delivery).
- **PUBLIC-001 — Public landing and documentation.** The public landing at `/` and documentation at `/docs` are unauthenticated and contain no installation data; the console lives at `/app` and its editor at `/app/monitor`, and every private document there still requires an owner session.
- **BOUNDARY-001 — Bounded delivery and operating claims.** Destinations apply to all monitors in the installation, while a single runner remains one network vantage. Provider acknowledgement and stored delivery state do not prove inbox receipt or human notification. Teams, Discord, SMS, on-call paging, incident escalation, and public status communication are outside the product; network isolation, browser execution, and accessibility conformance require separate evidence. See [Contact, interface and delivery](#contact-interface-and-delivery).

## Evidence and state

Every scheduled slot and attempt retains its monitor revision, policy, selected probes, runner version, start/completion, status, assertion results and error category. Retries are attempts inside a slot and never erase an earlier failure or increment scheduled confirmation/recovery streaks. Raw target response bodies and probe-request secrets are not retained in observations; notification destination credentials remain installation-local and are omitted from portable archives.

Target evidence, coverage, and notification delivery are independent. Healthy requires fresh, complete selected-probe coverage and the configured recovery threshold. Incomplete passing coverage is Unknown. A fresh failure below the fixed failure quorum is Degraded; meeting quorum and confirmation threshold is Failing even when coverage is incomplete. Expired evidence becomes Unknown without silently resolving an open incident. Recovery requires complete fresh passing scheduled slots. Runner errors and absent observations remain distinct from target failure. Scheduled incident transitions and their destination jobs are committed with the corresponding observation and state change; a test send is separate from that history.

Maintenance suppresses event emission while preserving observations and target state. After maintenance expires, a real completed slot may open a still-confirmed failure. Recovery requires a previously open trigger, preventing orphan recoveries. Pending means stored locally. Manual checks do not change scheduled cadence, confirmation or recovery.

## Integrity and authority

One self-run Node runner signs a purpose-separated enrolment with its installation key. The Worker records one installation-local runner identity and returns it on repeat enrolment and restart. Registered leases bind results to that identity; malformed, stale or invalid enrolment signatures cannot create authority or refresh contact. Scoped key-only clients remain supported. Registration and credentials stay outside portable archives. One identity is one configured network vantage, not proof that a key has only one process holder.

Slot identity is monitor/revision/due time; attempt identity includes slot/probe/attempt. Manual requests have distinct identities. Exclusive leases have bounded expiry; duplicate, expired, foreign or contradictory completion is rejected. Edited or paused inflight work remains historical evidence and cannot change current state or events. Missed cadence is counted without fabricated catchup results. Backward clock movement waits for due time; future evidence cannot establish health.

Observation, state and outbox writes share one durable transaction. Migration history is permanent. Completion verifies the immutable definition, fixed probe denominator, exact assertion bundle, outcome, clock bounds and transport limits. Live latency validation uses the larger retained elapsed measure. Historical archive compatibility does not relax live validation.

Every private document, mutation, observation read and export requires server-side operator or scoped runner authority. Missing configuration fails closed. Browser mutations bind the configured origin and reject cross-site requests. Loopback is not authentication. Shared Base operator-auth owns operator credentials and sessions; product policy must not silently grant additional roles. Signed reporting identifies the holder of the runner key; it does not prove an uncompromised runner.

## Network and credentials

Public HTTP(S) checks validate every A/AAAA answer and redirect hop, reject unsafe or mixed address sets, pin numeric sockets and retain original Host, SNI and certificate hostname verification. Proxy environments are bypassed. HTTPS downgrade is rejected; an origin change strips credentials, custom headers, request body and mutating method. DNS, redirects, body and retries have bounded execution. Responses are limited to 64 KiB; compressed responses are rejected. Independent network isolation remains an operating requirement.

Synthetic checks retain a separate live process/custody grant, exact path/port identity, expiry, GET/HEAD-only and no-redirect boundary. Grant authority is rechecked on every attempt.

Request headers, body and bearer/basic credentials are protected runner-local regular files with exact origin binding. Missing or invalid references yield runner errors without falling back to unauthenticated requests. Raw secrets and response bodies never enter observations, alerts or archives. Portable historical references are not receiving-installation execution authority.

Heartbeat tokens are owner-issued, hashed at rest, scoped to an immutable revision and rotated on issuance. Server receipt time and strictly increasing sequences prevent replay. Ingress alone cannot change state. A scheduled lease freezes an installation-local receipt snapshot; signed completion must match it. Missing, stale, future, paused, revision-mismatched or imported receipts cannot establish Healthy.

## Portability and retention

Versioned archives include definitions, immutable observations, state, outbox and an integrity digest. Restore validates bounded UTF8 bytes, schema, version, semantics and hash before transaction and requires an empty installation. Existing receiving-runner registration and idle contact do not make product data nonempty and remain unchanged by restore. Imported monitors gain new paused current revisions; leases are interrupted and alerts quarantined. Request execution references, heartbeat authority, sessions, keys, grants, contact and delivery credentials are installation-local and are not imported; destination definitions and notification histories are portable. Explicit receiving-owner reauthorization and enablement are required. No imported event or receipt automatically replays. A digest checks changed bytes, not trustworthy provenance.

There is no automatic observation metadata deletion. View limits (100 history slots and 200 outbox entries), monitor limits and archive limits are not deletion rules or measured storage capacity. Storage growth remains an operator responsibility. Deletion must never silently improve the configured denominator or historical health.

## Contact, interface and delivery

Authenticated runner contact records control-plane receipt time for accepted scoped claims, including idle claims, and accepted signed results. Owner reads, health checks and rejected requests do not refresh it. Fresh means within 120 seconds; future or unverifiable time is stale. Contact does not prove process liveness or target success. Restart retains it, archives omit it, and failed overview reads label contact unavailable with any prior timestamp clearly historical.

The interface exposes textual state, freshness, reasons, immutable revisions and manual provenance, with labels, keyboard controls and responsive layout. Failed reads show Unknown and last successful refresh. Action errors persist across polling; busy controls stay excluded through reconciliation. Editing must preserve configured checks; duplicated reserved typed assertion keys are rejected rather than silently overriding criteria. No fabricated uptime figure or color-only state is acceptable.

An enabled email, signed JSON webhook, or Slack incoming webhook destination applies to every monitor in that installation. Email uses the configured SendGrid sender and is submitted when the private runner polls; the runner sends webhook and Slack requests. The one-time test action queues a distinct test event and does not change monitor state. Only scheduled incident transitions create trigger and recovery notifications; maintenance suppresses these events, and manual checks do not create them. Portable archives include destination kind, name, enabled setting and available email address, but exclude webhook and Slack URLs, signing keys and other credentials. Restored destinations are disabled until the receiving owner reauthorizes and enables them.

Each event/destination pair has one automatic send attempt. HTTP 500, timeouts, connection loss, and unclassified responses remain uncertain without automatic resend. A successful provider or endpoint response means only that the request was acknowledged. It is not proof of inbox delivery, a person reading it, or an operational response. Authentication mail remains separate from incident email. A single runner is one network vantage; logical probe names do not establish geographic independence. Teams, Discord, SMS, on-call paging, incident escalation, and public status communication are outside scope. Browser execution, production network placement, recipient acceptance, and accessibility conformance require separate validation.

Notification endpoints and webhook signing keys are authenticated encrypted
at rest under installation-local Worker-secret custody. Retired credentials
are erased on rotation or deletion without deleting delivery history. Rotation
cancels queued work using the old credential; committed attempts cannot be
recalled. Slack uses its capability URL alone and has no Uptime signing key.
The key-bearing upgrade encrypts retained credentials, cancels obsolete queued
work and scrubs unused or terminal versions. A genuinely sending obsolete
version remains available only until its outcome. Individual undecryptable
credentials fail closed without disabling monitoring or sign-in; the owner can
re-enter or delete them. Email addresses are readable by the authenticated
owner; URL credentials and signing keys never appear in destination lists.
Destination comparison hashes use purpose-derived HMAC custody. An ahead
runner leaves queued work available to a correctly timed runner. Only an owned,
fresh and durably unstarted claim can return to the queue; its reservation
identity is retained separately from network attempts. Started, expired and
uncertain attempts are never automatically replayed.

### Complete product archive

The complete product archive includes notification destination kind, name, enabled setting and available email address, incident/outbox events, notification jobs, delivery envelopes, attempts, resolutions and received replay history. Email addresses are definitions decrypted only through the installation secret-bound custody implementation; unavailable active email definitions cause explicit export refusal. Deleted destinations whose credentials were previously erased retain their remaining definition. Webhook and Slack URLs, signing keys, credential versions, claims, sessions, runner/heartbeat authority, synthetic grants and request execution references are excluded. Schema 2 has an explicit versioned product-table extension; prior six-table schema 2 and legacy schema 1 remain accepted.

Restore preserves sanitized original state and notification history in a flat content-addressed archive-history ledger while live definitions are paused/disabled, queued or running slots interrupted, outbox quarantined and jobs prevented from dispatch. No imported event is replayed. Exports refuse named 10,000-row per-table, 100-monitor and 2 MiB bounds rather than truncate. Local `node scripts/rer.mjs export --output FILE` and `node scripts/rer.mjs import --input FILE --yes` use the same archive implementation as the console with private regular archive files and installation settings. Empty-installation validation covers product/history tables, including orphan histories. The explicit schema inventory classifies authentication identities, authorization audits, development sign-in mail and dispatch reservations as installation-local authority. Unknown tables or foreign integration namespaces cause named export refusal rather than omission. The replacement proof is `tests/archive-roundtrip.mjs`, which checks complete portable records and byte-preserved originals against each explicit inactive-restore transformation. The BASE-DATA-001 authority/credential exclusion remains pending owner confirmation; this contract does not claim that confirmation.


## Command contract

Uptime uses Base's portable rer CLI with Node 22.20.0 and pnpm 10.12.4. Setup requires an explicit first owner, uses ordinary Base outbox sign-in, preserves prior owner/data/settings and stops its temporary app. Dev provides real Vite assets/HMR. The canonical local state is `.wrangler/state`; unexpected state placement requires explicit recovery. Reset is confirmed and contained; builds exclude and restore private settings. CLI archives use Base integrity and named payloads around the existing complete Uptime archive and atomic inactive restore. The console archive format and historical restore policy remain supported. Remote CLI transfer is unavailable. Deployment and hosted acceptance remain separate.

Signed Assisted admission uses `/auth/owner-claim`, trusted installation bindings
and hidden setup credentials, followed by the same native owner session. A
second valid signature cannot replace a claimed owner. Native bootstrap remains supported.
`/api/editor/config` is an owner-only private no-store route; the editor receives
no setup, session or provider secrets. See `scripts/delivery/README.md`.
